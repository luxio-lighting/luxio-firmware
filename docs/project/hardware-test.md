Date: 21 October 2026. Board: LOLIN S3 Mini, ESP32-S3, 4 MB flash, 2 MB PSRAM. Strip: WS2805, 60 addressable controllers, GPIO 16. Tests used low global brightness (initially 16/255). Original flash backed up before installation; NVS preserved on application reflashes.

Observed five distinct physical outputs: red, green, blue, warm white and cool white. User explicitly confirmed all 60 controllers were dim red. Photo Booth's USB camera showed the strip and moving Lua colors. White-balance/exposure can shift perceived hues; no colorimetric claim is made.

Firmware's normal cloud URL was restored in build 3. Test-server certificates, databases and artifact endpoints are local only.

The browser uploaded Aurora to the actual device and received a run confirmation. Its UUID was `febce759-25c8-4c3f-979f-8429cf43c226`; it remained stored across the OTA. Temporary test scripts were deleted by the test programs. Tests restore their starting state; later user commands take precedence.

The iOS app was signed, installed and launched on the user's iPhone 16 Pro (`lighting.luxio.app`). The simulator runtime installed on the Mac is out of sync with Xcode, so a simulator UI session was not used; simulator compilation succeeded. Do not infer native UI validation from build success.

## iOS controls and strip fades — 21 October 2026

The iOS 0.1.2/build 3 update removes the redundant bottom navigation, Home icon and Home menu, capitalizes Luxio, uses custom brightness tracks, and puts stop icons on active preset tiles. Rainbow, Colorloop and four stationary Lua gradients are generated by `apps/ios/Luxio/Presets.swift`.

`node --import tsx tools/test-ios-presets.ts` executes the actual Swift-generated Lua at 1, 60 and 1024 pixels for every supported strip type. It checks spatial rainbow colors, uniform hue cycling, stationary gradients with exact endpoints, valid channel ranges and no white-channel mixing. `tools/test-transitions.cpp` exercises the firmware's 500 ms output crossfade, interruption continuity, independent channels, dimming, off, clock wraparound and normal animation frames after the fade. The Swift/TypeScript Protobuf interoperability check also passes.

Firmware diagnostic build 4 adds those output fades to color, brightness and animation changes. Matter remains disabled in this diagnostic build for the previously documented flash-size constraint. USB installation targets the active OTA slot identified from CRC-verified OTA metadata and preserves NVS and saved scripts. Visual timing and the final iOS layout still require review on the physical devices; the local iOS simulator remains unavailable due to its CoreSimulator version mismatch.

Physical follow-up passed on build 4: all nine iOS presets started, remained active through repeated Lua frames and brightness changes, and stopped successfully on the 60-controller WS2805 strip. The temporary test script was deleted and the pre-update animation and brightness restored. iOS 0.1.2/build 3 was signed and installed on the iPhone 16 Pro. Android was not changed.

## Editable iOS color wheel — 21 October 2026

The iOS 0.1.3/build 4 color editor replaces the native color picker with a full-screen hue/saturation wheel, numbered draggable stops, add/remove controls (one to eight stops), a start-to-end gradient preview, and the custom brightness slider. WS2805 also exposes a white-temperature wheel with independent warm/cool channels; WS2814 exposes its white channel. Single stops use the solid-color command. Multiple stops reuse one device-local Lua script with editable point metadata. The preview updates during dragging; device writes happen on release to avoid repeatedly writing flash during a gesture. Edits queued during a request are coalesced and sent serially.

`node --import tsx tools/test-custom-gradients.ts` validates the actual Swift wheel math, channel conversion, metadata round-trip/rejection and Lua output at 1, 60 and 1024 controllers across all supported strip types. Every pixel is checked against the expected interpolation; gradients remain still. The iOS device build passes. Final touch interaction and layout still need physical iPhone review because the local simulator is unavailable.

Physical tests passed on the 60-controller WS2805: one-, two-, eight-stop and mixed RGB/white gradients uploaded and remained running; updates reused the same script UUID, and stored sources retained their editable point metadata. Returning to a solid color stopped the gradient. The temporary script was deleted and the original strip state restored.

## Explicit Color / Gradient / Animation modes — 21 October 2026

Firmware diagnostic build 5 adds `State.mode` and persisted `Script.mode`. Color renders one color; Gradient executes setup once and holds the frame with Lua released; Animation keeps running loop. Brightness and power changes preserve mode. Stops, explicit colors, active-script deletion and runtime failures return to Color. Legacy scripts remain animations until explicitly saved as Gradient. The mode field is available through the shared HTTP, WebSocket, UART and BLE response schema.

The iOS 0.1.4/build 5 light screen has Color, Gradient and Animation selectors, with the wheel directly on the screen. Color exposes one point and color presets; Gradient exposes two to eight points and stationary presets; Animation exposes moving presets with their stop icons. iOS reads firmware mode and saves typed scripts. Android UI is unchanged.

TypeScript typecheck and all nine regression tests pass, including mode behavior, legacy compatibility, Protobuf and API tests. The Swift/TypeScript codec test verifies native decoding of the mode field. The custom-gradient pixel tests and iOS/firmware device builds pass.

Build 5 physical checks passed on the connected 60-controller WS2805: Color → Gradient → Animation → Color, power/brightness preserving mode, Gradient never executing an intentionally failing loop, and Animation runtime errors returning to Color. All nine iOS presets then passed with their explicit mode fields. The strip's original off state was restored. Firmware build 5 and iOS 0.1.4/build 5 are installed on the test devices.

## CLI color and gradient commands — 21 October 2026

CLI 0.1.1 adds `set-color <hex>` (`set` remains an alias) and `set-gradient <hex,hex,...>`. Inputs are case-insensitive, accept an optional `#`, and are validated before device access. Gradients accept 2–8 stops, reuse one saved script, set `Script.mode=GRADIENT`, and preserve global brightness. Device selection supports `--device`, `LUXIO_DEVICE`, or exactly one discovered light.

The built CLI passed 11 command cases against the protocol/Lua device server, including invalid input, RGB values, gradient endpoints, stationary output, script reuse and the legacy alias. Typecheck passes. Physical checks passed for `set-color ff0000` and `set-gradient Ff0000,00ff00,0000ff` over Wi-Fi and `set-gradient ff8000,0000ff` over USB; mode and brightness were verified. Initial USB uploads exposed the 256-byte CDC receive buffer limit; CLI requests now share one serial connection and pace uploads in 128-byte chunks. Tests restored the prior strip state and saved CLI gradient.

## 22 October — Matter Identify fade-blink (build 8)

Apple Home's Identify action had no output because the firmware did not register the Matter endpoint's Identify callback. Build 8 registers the callback and renders a temporary dim RGB-white pulse across the full strip: 500 ms fades, visible even when off. Normal animation frames keep advancing underneath. When Identify ends, output fades back to the current color/animation and brightness; no saved mode, script or brightness is changed.

The transition tests passed under address/undefined-behavior sanitizers: all 1024 pixels, off-state visibility, gradual rise/fall, repeated pulses, stopping partway through a fade, restoring updated colors and independent white channels, and timer wraparound. The Matter app builds at 2,256,944 bytes. SHA-256: `ff738f15492380b2cc734933b184495dc19a573304ab0878ecdd075bc4301641`.

A fresh private full-flash backup, including current Matter fabrics, was saved as `.sdk/before-identify-flash.bin` (mode 600). Only the application partition at `0x130000` was flashed. Build 8 is online; identity, configuration, brightness and color match the pre-flash snapshot. The user confirmed that re-pairing succeeded after a delay and that Identify now works.
