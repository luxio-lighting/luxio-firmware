## Release blockers and remaining work

1. **The selected recovery OTA architecture now builds within 4 MiB.** The user chose a fixed mini-loader and manual updates. The factory loader has 1.125 MiB and the Matter application has 2.5 MiB. Both size guards pass; the one-time A/B migration needs USB. See [recovery update design and verification](recovery-updates.md). Physical qualification is being recorded in the hardware test log; compilation is not a runtime pass.
2. **Matter and the Luxio Bluetooth service do not yet coexist.** The standalone GATT transport works, but the Matter build owns NimBLE. Register Luxio's service in the shared ESP-Matter GATT host and handle commissioning/advertising lifecycle together. The full Matter build currently has no Luxio BLE service.
3. **Matter interoperability/compliance is unverified.** Source uses the real SDK enhanced-color light and actual onboarding payloads. Commissioning with controllers, attribute synchronization back from Luxio commands, all required color modes, on/off brightness restoration, persistence/fabric reset, factory credentials/attestation and conformance tests need completion. Source integration and successful linking do not establish specification compliance.
4. **The complete integrated-radio ESP32 family is not qualified.** Only LOLIN S3 Mini hardware has been tested. GPIO reservations, RMT timing/channel order, flash profiles, USB/UART behavior and memory budgets on non-PSRAM boards need per-target work. Current maximum-size symbol/transport buffers are unsuitable for some smaller RAM configurations. WS2812 and WS2814 channel order/timing are not physically verified.
5. **Browser setup first-install has not been tested end to end.** esptool.js integration builds; serial framing and USB configuration work through the CLI. Actual browser port selection/flashing on Chrome and Edge, flash manifest layout validation and interrupted-flash recovery still need tests against release artifacts.
6. **HTTPS Studio → local HTTP across all browsers remains unresolved.** Localhost control is verified. Device CORS/private-network headers do not defeat browser mixed-content policy. Validate the actual hosted HTTPS origin on current Chrome, Edge, Safari and Firefox before selecting a solution with the project owner. No fallback or narrower browser scope is assumed approved.
7. **Native UI qualification remains.** iPhone installation/launch is verified; a full visual/accessibility/interaction pass and app icons are still needed. Android has build verification but no device/emulator UI pass. Realtime external-state synchronization and broader lifecycle/network failure testing remain. Native Bluetooth setup is intentionally v1.1, but Bluetooth control in firmware remains v1 scope.
8. **Release/deployment integration remains.** Each component now has its own local Git repository under `next/`. Active workflows live in the relevant repository; the former monorepo workflows are archived in `luxio-firmware/docs/project/previous-workflows`. Every repository now builds from its own checkout; shared source snapshots are local and CI needs no second checkout. Hosting destinations, secrets and store identities are not configured. Firmware workflow deliberately blocks release; update registration is a separate manual workflow until the complete firmware is qualified. Docker config exists; a container-image runtime smoke test is pending.
9. **Further resilience testing remains.** The recovery loader passed interrupted/corrupt downloads and reset during writing on the S3 Mini. Abrupt physical power removal, startup-failure fallback with the corrected loader, filesystem exhaustion and long-duration concurrent control still need qualification. Firmware Lua loop errors currently stop the animation without exposing a detailed runtime error to every client.
